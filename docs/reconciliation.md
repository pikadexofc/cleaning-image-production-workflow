# Safe reconciliation

`state.json` is authoritative. Per-page `slots.json` is refreshed after changed records are saved; if a process fails during a multi-file update, read authoritative state and repair only that page's mirror. Never infer approval from an older mirror.

`next` returns a `next_action`: generate, review, request_owner_approval or reconcile_existing_assignment. Generated work is reviewed before more generation on its current page. Reviewed pages may await owner approval while production proceeds on another page. Null means no work in that selection, not proof the whole project is finished; check status counts.

Source drift is intentionally conservative. It does not silently remap approved IDs when section order changes. Preserve the existing queue intact. Create a separate new queue from the new source folder. Prepare an explicit old-slot/new-slot mapping using page identity, heading, selector, role and asset hash. Have the owner confirm changed context/assignment mappings. Register existing owner assets into confirmed new slots and retain the old approval evidence and asset hashes. Review the new crop/context and obtain approval where its presentation changes. Do not hand-edit a global ordinal mapping or overwrite the old checkpoint. Unsupported inline/background/override mechanisms need a scoped extraction adapter before production; the parser recognizes nested image src and inline background URLs, not every CSS override system.

Existing source assignments are marked `existing_assignment` and are not generation candidates. They are not automatically owner-approved or job-verified. Resolve their actual local asset path and current owner status using permitted evidence. Run `import-existing --output <queue> --slot <id> --asset <matching-local-file> --evidence <direct-owner-confirmed-mapping>`. This preserves the original source URL and import evidence, copies a versioned asset, and leaves it generated/awaiting review rather than approved. Never use this command to substitute an unrelated or AI-created image for the existing owner assignment.

After three attempts, `authorize-retry --evidence <direct-owner-authorization> --approach <changed-method>` opens another bounded cycle while retaining all earlier versions. This is a recorded authorization, not automatic escalation or permission inferred from a deadline. Each illustrative generation requires a fresh equipment preflight record.

State writes use an OS lock and revision comparison. A stale writer fails instead of erasing progress. If an asset was copied before a failed state save, it may remain as an orphan version. Preserve it, reload the checkpoint and reconcile its hash; do not delete it blindly or repeatedly rerun the same write. There is intentionally no concurrent generation worker pool.

Review/approval evidence fields are operator attestations. The CLI checks required fields, states and file hashes, not whether a screenshot was truly inspected or an owner message is authentic. The agent must never fabricate either. Image decoding and dimensions need an actual technical check before visual review; tests of state transitions use synthetic file bytes and do not establish visual QA.
